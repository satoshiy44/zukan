# 素材の置き場所

`assets/src/` に `saboko_1.png` 〜 `saboko_11.png`（1が最小、11が最大）を置いて、
ビルドコマンドを1回走らせるだけです。

```
npm install          # 最初の1回だけ
npm run build:assets # 素材を追加・差し替えたら毎回
```

これで `assets/shapes.js` が作られ、ゲームが自動で使います。
素材がまだ無い段階は仮の丸を描くので、絵の完成を待たずに遊べます。

## 元画像の条件

| 項目 | 内容 |
|---|---|
| 置き場所 | `assets/src/saboko_1.png` 〜 `saboko_11.png` |
| 形式 | PNG（**背景が透明**であること）。拡張子は `.png` / `.PNG` どちらでも可 |
| サイズ | 自由。正方形にする必要も、余白を詰める必要もありません |
| 縦横比 | 自由。横長でも縦長でもそのままの形で使われます |

透明な余白はビルド時に自動で切り落とされ、その段階で実際に表示される大きさに合わせて縮小されます
（`TIER_SIZES` の2.5倍）。元画像は大きいまま置いておいて構いません。

## 当たり判定は「絵の形そのまま」

不透明な部分の輪郭をたどって、その多角形が当たり判定になります。丸ではありません。
横長の絵は横長に転がり、でこぼこした絵はでこぼこに引っかかります。

そのため元画像で気をつける点：

- **半透明のフチやゴミは消す。** アルファ値64以上を「ある」と判定するので、
  切り抜き時の薄いモヤが残っていると当たり判定が膨らみます
- **離れた小さいパーツは無視されます。** いちばん大きい塊だけを判定に使うので、
  本体から完全に離れた飾り（浮いたハートなど）は絵としては描かれますが当たりません
- **細すぎる部分は避ける。** 髪の毛1本のような細い突起は、物理的に引っかかって
  積み上がりが不安定になります

## 確認のしかた

`index.html?debug` で開くと、当たり判定の輪郭がオレンジ色で重なって表示されます。
絵とズレていないか、変な形に分割されていないかをここで確認できます。

## 段階ごとの大きさ

`game.js` の `TIERS` の `r` が「その段階の大きさの基準になる半径」です。
**絵の面積が円 πr² と釣り合うように**自動で拡縮されます。

長辺ではなく面積を基準にしているのは、体感の大きさが面積で決まるからです。
長辺をそろえると、横長で隙間の多い絵（ギターの回）は幅こそ広いのに小さく見えてしまいます。

| 2 | ちびさぼこ | 17 |

自動計算の結果を1枚だけ手で調整したいときは、その段階に `scale: 0.9` のように
書き足すと倍率がかかります。
